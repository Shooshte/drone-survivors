# 3D Drone Implementation Plan

> **For agentic workers:** Use executing-plans to implement this plan task-by-task.

**Goal:** Port the arena and drone to 3D with bounded vertical flight.

**Architecture:** Keep input, movement, bounds, and reset in `src/arena.rs`.
Keep mesh rendering, camera, lighting, and ground marker in `src/arena/scene.rs`.
Exercise the real movement systems from `src/arena/tests.rs` without a GPU.

**Tech Stack:** Rust nightly, Bevy 0.19.1, existing dependencies only.

## Global constraints

- X/Z arena: 960 × 540; Y range: 0–300; start: (0, 90, 0).
- Drone half-extents: (18, 6, 18); speed: 240 units/second.
- WASD/arrows horizontal; Space up; either Shift down; R reset; Escape quit.
- Normalize all three input axes together and clamp the entire drone.
- Preserve worktree isolation; push `codex/drone-3d` and open a PR against main.

## Task 1: Movement and bounds

- [x] Convert test positions/expectations to Vec3 and assert the approved start.
- [x] Cover six directions, aliases, all two/three-axis diagonals, release,
  opposing keys, frame-rate independence, all 26 boundary directions,

- [x] Run `cargo test --locked`; confirm failures against the old 2D controller.
- [x] Replace 2D input with `Vec3::new(horizontal, vertical, depth)` and normalize.

  center + half_size - DRONE_HALF_EXTENTS)` after time-scaled movement.
- [x] Run `cargo test --locked`; all movement tests must pass.
